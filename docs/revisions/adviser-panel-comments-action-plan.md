## Work included in the merged revision

- Payment and fee authority is narrowed to Barangay Admins, with role regression coverage.
- Synthetic dashboard fallback counts are removed and empty chart states are displayed honestly.
- Resident document requirements are rendered as a preparation checklist in web and mobile.
- Admin document offerings use common requirement checkboxes with custom additions; the existing request snapshot keeps prior requests' published rules stable.
- A released request can receive a separately printed certificate-verification QR after an Admin confirms the paper certificate was issued.
- Mobile push open events preserve the ticket/request identifier and show that specific record.
- Android `minSdk` is explicit at API 24.
- Polling intervals and queue lock behavior are documented without claiming WebSockets or guaranteed delivery.
- Resident mobile offers encrypted, account- and Barangay-scoped read-only offline snapshots for announcements, hotlines, and the resident's document, queue, aid, and issue requests; it does not replay writes.
- Targeted web/mobile test results and the backend test limitation are recorded in the [revision verification log](revision-verification-log.md); they are not treated as study respondents or penetration-test findings.
